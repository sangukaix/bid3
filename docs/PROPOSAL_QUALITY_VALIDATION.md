## 2026-10-12 실제 공고 초안·페이지별 수정 검증

나라장터 공고 `R26BK01759488`의 공식 제안요청서 HWP와 입찰공고 PDF로 실제 서비스 생성·수정 흐름을 실행했다. 과거 회사 제안서는 프로젝트 참고자료로 사용하고, 미검토 회사 근거를 자동 승인하지 않았다. 생성·보완 과정은 로컬 Gemma4:26b만 허용하고 클라우드 SDK 통신을 차단했다. 사용자 원본과 기존 제안서의 SHA는 유지됐다. 계정 자료·출력 파일·호출 로그는 Git에 포함하지 않는다.

번호를 붙인 여러 페이지의 수정 요청을 모델에 함께 전달하면 재사용되는 `shape-*` ID 때문에 다른 페이지의 지시가 섞이는 사례를 확인했다. `N페이지:` 형식의 메시지는 공통 지시와 해당 페이지 요청만 전달한다. 모델이 대상 ID 자체를 실제 교체 문구로 반환하면 저장 전에 거절한다. 정성제안서 표의 `최대 40쪽`과 같은 앞쪽 상한 표현도 원문 근거가 있을 때만 분량 제한으로 인정한다.

최종 초안은 34쪽이며 공고 원문의 40쪽 이내다. 전체 PDF 축소판과 표지·목표·일정·품질관리·상세 답변 등을 확대 확인했고 코드상 심한 넘침·작은 본문·빈 페이지는 0개였다. 최종 검수의 기술 실패는 0개, 본문 수행 계획 46개는 모두 배치됐고 본문 인용 대조는 44/46개였다. 이 수치는 조건 충족이나 평가 점수가 아니다. 확인 필요 문구 20개, 회사 관련 확인 대상 6건, 27쪽의 대괄호 목록 3개에 대한 자리표시자 경고와 반복 레이아웃 안내는 남는다. 별도 서류·자격·가격도 제출 완료 처리하지 않는다.

공유 HTTPS 주소에서 인증 조회·PDF 미리보기·제출 전 점검은 200, 미인증 조회는 401, 초안의 최종본 다운로드는 409로 확인했다. 편집 가능한 PPTX와 A4 검토용 PDF를 별도로 보존하고 최종 34쪽을 모두 확대 확인했다. 서버 전체 378개 테스트가 통과했다. 실제 제출용 확정본은 아니다.

## 2026-10-12 짧은 문구 재작성 보완

실제 로컬 생성에서 긴 본문을 줄이는 응답이 `확인 필요`를 누락하거나, 날짜 범위의 앞부분만 반복하여 길이·완결성 검사에 실패하는 사례를 확인했다. 기존 두 번의 재작성 범위를 유지하면서 필수 확인 문구와 앞서 거절된 후보를 다음 요청에 전달한다. 날짜의 연·월·일과 조정 가능 조건을 보존하며 공백을 줄여 표현하도록 안내한다. 문구 잘라내기나 검사 우회는 하지 않는다.

확인 조건이 빠진 후보를 거절하고 다음 응답으로 복구하는 회귀 검사를 추가했다. 서버 전체 376개 테스트와 마지막 프롬프트 변경 후 관련 14개 테스트가 통과했다. 모델의 의미 보존을 완전히 보장하는 검사는 아니므로 실제 출력의 원문 대조는 계속 필요하다.

## 2026-10-12 HWP 표 추출 보완

실제 신규 공고의 HWP 제안요청서를 확인하면서 pyhwp 기본 `hwp5txt` 변환이 표를 `<표>` 표시로 대체하고 셀 내용을 건너뛰는 문제를 발견했다. 같은 설치 패키지의 XML 변환을 제한 시간 내 별도 프로세스에서 실행하고 본문과 표의 행·셀 텍스트를 순서대로 읽도록 수정했다. 배점·분량·제출 기준과 중첩 표도 읽으며, 스타일·글꼴 정보는 본문에 넣지 않는다. 실제 RFP의 40쪽 제한과 기술평가 배점표를 다시 추출해 확인했다.

인덱스 버전은 3이다. 이전 HWP 키워드 인덱스는 최초 사용 시 새로 추출하고, 실패하면 기존 저장 파일을 유지한다. 기존 요구사항 캐시는 새 원문 서명과 다를 경우 재생성한다. 스캔 이미지·도형 안의 글자나 표의 시각적 병합 관계를 완전히 복원하는 기능은 아니므로 원본 대조는 여전히 필요하다.

작성 계획은 본문, 별도 서식, 자격·증빙, 가격, 담당자 분류 확인으로 나눈다. 보수적인 규칙 분류이므로 원문 대조가 필요하다. 본문 항목에는 수행 방법·담당 역할·일정·산출물·검증 방법과 회사 근거 후보 ID를 연결한다. 한 개의 명시된 배점만 페이지 배분 가중치로 사용하며 합계·범위·복합 배점은 추정하지 않는다. 배분은 원본 양식에 대한 작성 제안이고, 실제 답변 반영은 최종 출력 인용으로 별도 확인한다. 근거 후보 연결은 자격 충족이나 제출 완료가 아니다.

신규 생성은 선택한 양식의 사진·회사 화면·도식·표와 본문 구조를 유지합니다. 항목별 수행 방법과 필수 수치는 짧은 문구로 풀고, 요구사항 원문·상세 수행 설계·확인 질문은 작성 계획과 별도 검수 PDF에 보존합니다. 2026-10-17부터 보고서형 조건별 상세 페이지의 자동 추가를 제거했습니다. 검수표 분리는 필수 내용 생략 허용이 아닙니다. 공고가 특정 준수표·서식을 제출하도록 요구하면 해당 원문이 우선이며, 현재 본문에 반영되지 않은 조건은 그대로 미확인으로 남습니다.

기존에 생성한 상세 페이지의 이름 있는 답변·질문 상자는 계속 읽고 출력 위치를 연결합니다. 원문 조건만 반복한 상자는 요구사항 답변 검수에서 제외합니다. 신규·기존 모두 실제 출력의 수행 답변·조건·수치·미확인 표현을 대조합니다. 회사 주장 검수는 고정 텍스트·표·그룹을 포함하고, 숫자 모순 후보에서만 원문 재인용·제목·꼬리말·관리 ID를 제외합니다.

모순 검수는 숫자가 있는 문장에서 공통 단어가 있고 숫자·단위가 다른 쌍을 대상으로 한다. 실제 인용·페이지가 확인된 후보만 표시한다. 모집단·시점·목표/실적이 다른 경우 모순으로 단정하지 않도록 지시한다. 숫자가 없는 논리 모순이나 차트·이미지의 텍스트, 모든 의미 모순을 탐지하는 기능은 아니다.

## 웹 사용과 긴 작업

입찰 제안서 화면의 **평가항목별 작성 계획 · 제출 업무**, **최종 문서 전체 AI 검수**에서 확인한다. **현재 파일 전체 AI 검수**는 검수 기록만 갱신하고 파일은 수정하지 않는다. 파일·회사 근거 변경이나 만료 시 저장된 전체 검수는 이전 기록으로 표시한다. **최신 파일 대조**는 저장된 인용의 코드 검사이며 새로운 AI 의미 검수와 다르다.

웹의 새 생성과 전체 검수는 `ProposalTask`에 저장하고 별도 로컬 Python 프로세스에서 처리한다. 브라우저를 닫거나 Django를 다시 시작해도 시작한 작업은 계속된다. 웹 재접속 시 상태·단계·묶음 수를 불러오며 같은 프로젝트의 활성 작업은 한 개다. 실행 중 수정·확정·휴지통 이동을 차단한다. PC/worker 종료 시에는 완료되지 않으며 중단 감지 후 실패로 표시하고 다시 요청할 수 있다. 기존 파일은 보존한다. 분산 서버용 큐는 아니다.

새 환경은 `server\venv\Scripts\python.exe server\manage.py migrate`로 `0024_proposaltask`까지 적용한다. 기존 DB는 먼저 백업한다. 작업 로그·인증 정보·실제 검증 결과는 비공개 `server/media/`, `.local/`에 둔다.

## 반복 가능한 검증

`server/bids/fixtures/proposal_quality_cases.json`에는 교육(R26BK01637158), IT 라이선스(R26BK01635679), 안전진단(R26BK01628456)의 저장된 공고 원문에서 확인한 일부 조건, 수동 예상 판정, 원문 SHA-256·URL·확인일을 기록했다. 시간 단위·계약기간 변경, 증빙 없는 인증 주장, 수치 모순을 의도적으로 넣은 자료이며 실제 제출 제안서가 아니다. 최신 정정공고 확인 여부는 **false**다.

저장소 루트에서 실행한다:

```powershell
cd server
venv\Scripts\python.exe manage.py test --noinput
cd ..
server\venv\Scripts\python.exe server\manage.py evaluate_proposal_quality server/bids/fixtures/proposal_quality_cases.json --output .local/verification/proposal-regression.json
cd web
npm run lint
npm run build
```

회귀 검증은 PROPOSAL·CLAIM_REVIEW가 Ollama일 때만 실행한다. 기대 판정 불일치·검수 실패·수동 기준 미등록 시 결과를 저장하고 실패 종료한다. 입력 파일과 DB는 변경하지 않는다. 기준과 일치했다는 결과를 실제 입찰 전체 품질 점수로 해석하지 않는다.

실제 생성 파일은 비공개 manifest에 다음 형식으로 등록한다. 경로는 manifest 폴더 기준이다. `pptx` 대신 `slides` 문자열 목록을 넣으면 메모리에 검증용 PPTX를 만든다.

```json
{"cases":[{
  "name":"실제 공고 검토 사례", "pptx":"draft.pptx",
  "approved_evidence":"reviewed-company-evidence.txt",
  "source":{"file":"original-rfp.pdf","latest_correction_verified":false},
  "requirements":[{"requirement":"원문에서 확인한 조건","sources":["제안요청서 3쪽"]}],
  "expected":{"requirements":{"R0001":false},
    "claims":[{"text":"검토할 회사 주장","status":"review_required"}],"conflict_count":0}
}]}
```

`approved_evidence`는 담당자가 확인한 근거 텍스트로 원문·조건·유효기간을 보존해야 한다. manifest 표시는 진위나 최신성 인증이 아니다. 실제 제출 검증에는 최신 정정공고, 공고 전체의 수동 기준표, 실제 회사 증빙, 별도 서식·가격, PPTX와 렌더링 PDF의 시각 확인이 추가로 필요하다.

## 후속 MVP: 독립 대조와 읽기 쉬운 상세 페이지

사용자 최종 검수 전에 AI 오판과 읽기 문제를 추가로 보완했다. 모순 재대조에서는 앞선 검수자의 설명을 전달하지 않고 실제 두 인용만 전달한다. 전용 답변 상자의 전체 수행안과 연결된 공고 조건을 함께 제공해 강사/학습매니저처럼 다른 역할이 섞이지 않도록 했다. 재대조가 같은 대상·지표·시점이라고 판정해도, 두 원문에서 직접 복사한 수치·단위의 차이까지 코드로 확인해야 자동 보완 가능한 모순 후보가 된다. 같은 수치, 서로 다른 지표, 확인할 수 없는 값은 경고로 남기고 자동 보완하지 않는다. 분/시간·일/주·통화와 완전한 날짜의 동등 표현을 대조하며 달/일 변환은 추정하지 않는다. 250명의 일부인 50명을 인용한 것처럼 통과시키지 않도록 숫자 경계도 확인한다.

이전 출력의 비교 경고 10건만 재대조한 시험은 9건을 양립 가능으로 제외하고, 발주기관이 포함된 사업명과 참가업체 익명성을 혼동한 1건은 불확실한 경고로 유지했다. 임의로 경고를 삭제하거나 사실을 고쳐 쓰지 않았다. 이 시험은 해당 후보의 재대조이며 문서 전체 모순 검출 정확도의 측정이 아니다.

정량적 평가 표현과 제안서 작성·제출·발표·목차, 평가·탈락 규정은 수행 답변과 분리해 원문을 담당자 점검 목록에 보존한다. 알려진 별지/서식은 기존 서식 분류가 우선한다. 별도 단일 배점이 명시된 정성 평가 항목은 본문 답변과 가중 배분 대상으로 유지하며, 합계·복합 배점의 평가 안내와 구분한다. 실제 투입·수행을 계획하는 강사·매니저 조건도 본문에 유지한다. 해당 교육 공고는 분류 변경 후 본문 61개와 별도 제출 업무 109개이며 전체 원문 조건 170개는 유지된다. 분류는 보조 규칙이므로 복합 조건은 담당자가 원문과 대조해야 한다.

긴 답변은 원문 조건을 왼쪽에, 수행안·검증·확인 질문을 오른쪽에 놓는 가로형 카드로 배치한다. 짧은 답변은 두 열 카드로 유지한다. 원문이나 답변을 잘라 넣지 않고 12pt를 유지하며 기존 페이지 상한·미배치 보고도 유지한다. 제목에는 원문 분류를 사용하고 기본 양식의 알려진 작은 출처·마무리 안내 글씨는 11pt로 키웠다. 업로드 원본에 이 기본 양식 정리를 적용하지 않는다. 기존 작성 계획으로 만든 격리 시각 시험본은 34쪽, 본문 61개 배치·누락 0개, 작은 본문·심한 예상 넘침 0개였다. PowerPoint PDF 전체 축소판과 가로형 상세 페이지를 확대 확인했다. 실제 새 생성의 수치와는 구분한다.

실제 Gemma 회귀 사례는 기존 4개에 서로 다른 강사·학습매니저 역할을 추가한 **5개**가 통과했다. 의도적으로 넣은 회당 30분/30시간 오류는 불확실 경고로만 낮춰 통과하지 않도록 수치 차이까지 확인된 후보 수 1개를 별도 기대값으로 검사한다. 웹의 기존 '제안서 만들기' 버튼은 이미 만들어진 초안을 확정하는 동작임을 드러내도록 '최종본으로 확정'으로 바꿨다. 확정이 자격·회사 증빙·제출 적합성 인증을 뜻하지 않는 정책은 유지한다.

기본 양식의 마무리 제목이 정확히 '확인 필요'인 경우는 사실을 추가하지 않는 '성과 목표와 검증 계획'으로 정리한다. 미정 KPI 값의 '확인 필요' 표시는 유지한다. 이전 출력의 격리 복사본을 다시 렌더링하여 제목 교체와 미정 값 보존을 확인했다.

후속 시험에서는 재시도 후에도 긴 연속 인용이 300자 상한을 넘으며 묶음 전체가 실패했다. 원문 조건을 잘라 통과시키지 않도록, 인용의 허용 상한을 600자로 조정하고 실제 파일 재대조에도 같은 상한을 적용했다. 페이지의 정확한 연속 원문·수치·단위·날짜·미확정 표현 검사는 그대로 유지한다. 반영하지 못한 경우는 빈 인용을 반환하도록 명시했다. 300자 이후에 있는 수치 조건까지 유지·대조하고, 그 조건이 바뀐 파일은 미반영으로 판정하는 회귀 검사를 추가했다.
