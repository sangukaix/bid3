# 로컬 AI 전환 점검 (2026-09-10)

OpenAI API 잔액 없이 사용하는 경로를 구현하고 개인 노트북의 server/.env에 AI_MODE=local을 적용했다. 기존 비공개 설정은 .backups/local-mode-*에 백업했다. 설정 파일과 사용자 자료는 Git에 포함하지 않는다.

## 구현

- 로컬 모드에서는 모든 텍스트 역할을 Ollama로 보내고 OpenAI SDK 및 벡터 임베딩 호출을 차단한다. 잘못된 AI_MODE 값도 오류 처리한다.
- 문서 검색은 한국어 키워드 색인을 사용하며 기존 Chroma 벡터를 보존한다.
- Qwen3 14B는 채팅·분석·회사 지식·요구사항·제안서·정량서식을 담당한다.
- Gemma4 26B는 사업자등록증 이미지·스캔 PDF를 읽는다. 텍스트 PDF는 Qwen을 사용한다.
- 긴 근거는 분할 요약하고 캐시한다. 슬라이드 원문과 사용자 지시는 요약하지 않는다.
- 로컬 PPTX 생성은 기존 페이지의 정확한 텍스트 위치에만 적용한다. 자동 추가·삭제는 지원하지 않는다.
- 다른 페이지 유지가 명시된 수정은 호출 전에 페이지 범위를 제한한다.
- 정량서식의 미제공·확인 필요 문구 및 직접 확인 항목은 작성 완료로 집계하지 않는다.
- 웹 검색 요청은 공개 검색/URL 조회로 처리한다. 검색 실패를 명시하고 출처를 만들어내지 않는다.

## 실제 검사

가상 회사와 공고를 사용하여 Qwen 요구사항 추출, 회사 지식 추출, 공고 분석, 전략, 정량 JSON 및 DOCX 생성, 장문 요약을 실행했다. Gemma는 가상 사업자등록증 이미지와 스캔 PDF에서 회사명·등록번호를 정확히 추출했고 텍스트 PDF 검사도 통과했다. 공개 URL https://www.python.org/ 조회가 성공했다.

초기 PPTX 검사에서 파일 생성 성공만으로는 확인할 수 없는 문제를 발견했다. 기존 문구 잔존, 부정확한 수정 위치, 요청 외 페이지 수정 문제를 출력 구조 및 범위 제한으로 보완했다. 최종 가상 3장 PPTX에서 기존 사업 문구 교체와 페이지 수 유지, 첫 페이지 제목 변경, 다른 두 페이지의 텍스트 보존을 파일 내용으로 검증했다.

API와 웹의 HTTP 200, Django 시스템 검사·마이그레이션 상태를 확인했다. 최종 전체 자동 테스트 156개가 39.6초에 통과했다. 프런트엔드 코드는 이번 전환에서 수정하지 않았으며 이전 점검의 lint/build 결과는 별도 진행 기록에 있다.

## 검증의 한계와 후속 작업

실제 회사 자료로 만든 대형 제안서의 제출 품질 검증은 완료되지 않았다. 3장 가상 문서의 기능 검사이며 모든 템플릿의 시각적 배치·글자 잘림을 보증하지 않는다. 로컬 출력에도 증빙 서류와 인력현황 표를 혼동하는 문구가 관찰되어 원문 및 회사 증빙과 대조해야 한다. 요약과 자동 요구사항 반영 점수도 사실 검증을 대신하지 않는다.

다음 품질 과제는 실제 공고·회사 증빙으로 누락률과 근거 일치 평가, 템플릿 시각 검수, 장시간 생성 작업 큐 전환이다. docs/TODO.md의 과거 미완료 항목 전체를 완료한 것은 아니다. 상위 Qwen은 설치하지 않았으며 14B와 26B의 숫자만으로 품질을 판단하지 않는다.
