# 발표자료 작업실

입찰과 별개인 `/dashBoard/presentations`에서 학원·수업·프로젝트 발표를 작성합니다. 회사정보나 입찰 자료가 자동으로 섞이지 않습니다. 기본 모델은 **Ollama `gemma4:26b`**이며 OpenAI 호출이나 유료 폴백은 없습니다.

## 사용 순서

1. 왼쪽 **발표자료 작성하기 → 새 발표자료**를 엽니다.
2. **작업 중인 PPTX 이어서**에서 미완성 파일·희망 양식을 업로드합니다. 기본 디자인이나 저장한 개인 양식으로 시작할 수도 있습니다.
3. 각 페이지의 **원본 유지**를 선택한 뒤 **현재 양식과 유지 설정으로 시작**을 누릅니다. 잠긴 페이지도 새 페이지의 디자인 원본으로 복제할 수 있습니다.
4. 상단 **참고 URL / 참고자료 업로드 / 이미지 업로드**에서 자료를 추가합니다. **지침·참고자료**에서는 선택 사항인 instruction, 참고 텍스트, 자료 사용 여부를 관리합니다. 관리자 계정은 서버 PC의 절대 파일/폴더 경로도 읽을 수 있습니다.
5. Gemma 대화에서 범위를 선택합니다: 방향 의논 / 현재 페이지 수정 / 기존 페이지 유지하고 이어 만들기 / 잠금 해제 페이지 전체 재작성.
6. 질문이 있으면 답변을 보내 새 작성안을 받습니다. 작성안의 내용·페이지 범위를 확인한 뒤 **이 작성안 적용**을 누릅니다. 질문에 답하는 것만으로 파일이 바뀌지 않습니다.
7. 스크롤 방식의 실제 PPTX 미리보기와 **작성 검수** 결과를 확인합니다. 왼쪽 번호로 페이지를 선택하고 텍스트·표 셀·글자 서식을 직접 수정하거나 상단에서 PNG/JPG를 삽입합니다. 이전 버전 복원은 **버전·작업 연결**에서 합니다.
8. **내 양식으로 저장**하면 현재 내용과 디자인, 유지 페이지 설정을 개인 템플릿으로 재사용할 수 있습니다. 수정은 그 양식으로 새 작업실을 만든 뒤 다시 저장합니다.

예시: “기존 5장은 유지하고 구현 과정과 회고를 3장 이어 만들어 줘. 3쪽 디자인을 사용하고, 근거 없는 성과 수치는 쓰지 말고 먼저 질문해 줘.”

## 참고자료와 PC 경로

- 파일: PDF, DOCX, PPTX, TXT/MD/CSV/JSON, 소스 코드, PNG/JPG. 이미지는 Gemma의 시각 입력으로 설명을 추출해 참고합니다. 이미지 자체 삽입은 별도로 선택합니다.
- 웹: 공개 HTML·텍스트·PDF. 로그인·동적 화면·웹 검색은 지원하지 않으므로 필요한 본문을 업로드하거나 붙여넣습니다. 내부 IP, 로컬 주소와 그쪽으로의 리디렉션은 차단합니다.
- 경로: **BID3 서버가 실행되는 PC 기준**입니다. 다른 팀원의 PC 파일은 업로드합니다. 폴더는 소스 코드만 읽으며 `.env`, 인증정보 파일, `.git`, `node_modules`, 가상환경 등은 제외합니다. 코드를 실행하거나 VS Code를 제어하지 않습니다.
- 웹·경로 자료는 AI 요청마다 새로 읽습니다. 긴 자료는 관련 발췌를 골라 입력 길이 안에서 사용합니다. 대화에 사용 자료와 제외 자료 수가 표시됩니다. 모든 파일 전체를 한 번에 이해하는 기능은 아닙니다.
- 원문이 없는 스캔 PDF의 OCR은 지원하지 않습니다. 해당 페이지를 이미지로 올릴 수 있습니다.
- **버전·작업 연결 → Codex 전달용 작업 설명 다운로드**로 PPTX 경로·지침·참고자료·최근 대화를 전달합니다. 웹 앱이 Codex에 자동 접속하지는 않습니다.

## 편집 범위

업로드 원본은 첫 버전으로 남습니다. OOXML 패키지의 필요한 부분만 수정하며, 잠긴 슬라이드 XML과 관계 정보가 바뀌면 저장을 거절합니다. 변경하지 않은 배경·도형·마스터·차트·이미지는 유지합니다. 새 페이지는 기존 페이지 디자인을 복제합니다.

직접 편집은 텍스트·표 셀, 글자 크기·색상·굵기, 이미지 삽입, 페이지 복제·순서·삭제를 제공합니다. 텍스트 교체 시 해당 상자의 첫 문단 서식을 이어 쓰므로 상자 내부의 혼합 서식은 통일됩니다. 자유로운 도형 그리기·드래그 배치·차트 데이터 편집·새 이미지 생성은 제공하지 않습니다. 사진으로 평탄화된 슬라이드는 이미지 안의 글자를 편집할 수 없습니다. 정밀한 디자인 조정은 PPTX를 내려받아 PowerPoint에서 작업한 뒤 다시 업로드할 수 있습니다.

페이지 복제·순서·삭제 API는 유지하지만 해당 버튼은 작업실 화면에서 제외했습니다. **텍스트 상자 내용 수정**은 기존 상자의 문구와 서식을 직접 바꾸는 기능입니다. AI가 내용을 구성하도록 하려면 오른쪽 Gemma 대화를 사용합니다.

## 작성 검수와 보완

AI 작성안을 적용하면 저장 전에 폰트 폭·상자/병합 셀 크기·여백·줄 간격으로 표시 공간을 추정합니다. 필요한 경우 글자 크기를 줄이되 일반 텍스트는 11pt 아래로 줄이지 않으며, 원래 작은 표기는 원래 크기를 유지합니다. 공간이 부족하면 문장을 중간에서 자르지 않고 보완 대상으로 보냅니다. 입찰 제안서도 같은 측정 함수를 사용하며 제목의 최소 크기는 기존 18pt를 유지합니다.

발표자료는 Gemma4가 요청 누락, 원문과의 모순, 미제공 수치·완료 주장과 중요한 미확인 조건을 별도로 검토합니다. 중대 문제가 있으면 해당 상자만 **한 번 보완한 뒤 재검수**합니다. 중대 문제가 남으면 전체 적용을 중단하고 기존 버전을 보존합니다. 보완에 추가 설명이 필요하면 대화에서 질문합니다. 가벼운 경고는 저장하되 **작성 검수**에 Gemma의 확인 제안으로 표시합니다. 같은 모델의 검수는 정확성 보증이 아니며 실제 배치도 PowerPoint 미리보기로 확인해야 합니다.

새 페이지·전체 재작성은 상자의 위치와 크기를 전달하고 제공한 제목·본문 target을 모두 작성했는지 검사합니다. 기본 양식의 고정 각주·페이지 번호와 텍스트가 없는 배경 도형·구분선·화살표는 AI 대상에서 제외하고, 그 위치로 제안된 AI 수정도 거절합니다. 업로드된 빈 텍스트 상자·플레이스홀더·표 셀은 작성 대상으로 유지합니다. 이전 버전의 목록은 빈 표 셀을 제외한 빈 개체를 보수적으로 제외하므로, 이전에 올린 양식의 빈 텍스트 상자까지 AI가 채우려면 다시 업로드하세요. 직접 편집 범위는 유지합니다. 형식이 잘못됐거나 출력이 중단되면 완성되지 않은 응답을 버리고 같은 모델로 최대 한 번 다시 요청합니다. 유료 대체는 없습니다.

반복되는 JSON 행은 원래 열/셀 값과 타입을 복원할 수 있는 무손실 표로 전송합니다. 긴 페이지의 원문·target을 임의로 잘라 보내지 않으며, 지침/현재 페이지가 입력 한도를 넘으면 사용자에게 분할을 요청합니다. 참고자료를 제외한 경우 실제 사용 ID와 제외 수를 기록합니다. 검수의 출처 ID·발췌 번호가 제공된 자료에 존재하는지 코드로 확인하고 버전별로 기록합니다. 이 검사는 출처 문구가 주장을 실제로 증명하는지에 대한 완전한 판정은 아닙니다. 직접 편집하면 이전 AI 검수 결과를 새 버전에 재사용하지 않으며 같은 파일을 복원하면 해당 버전의 검수 기록을 함께 복원합니다.

업로드된 모든 PPTX의 시각적 동일성을 보장하는 것은 아닙니다. 서버에 없는 폰트, 특수 개체나 복잡한 미디어가 있으면 미리보기와 PowerPoint에서 확인하세요. 외부 연결 개체는 파일 안에 포함한 뒤 업로드해야 합니다.

## 실행·운영

기존 실행 명령을 사용하며 최초 업데이트 후 `server/venv/Scripts/python.exe manage.py migrate`가 필요합니다. PowerPoint 또는 LibreOffice가 설치되어 있어야 미리보기를 만들 수 있습니다. 모델 설정은 서버 `.env`의 `PRESENTATION_LOCAL_MODEL=gemma4:26b`, `OLLAMA_BASE_URL`, `LOCAL_LLM_TIMEOUT`을 사용합니다. 입찰 기능의 라우팅과 독립되어 있으며 현재 유지보수 라우팅 화면에서는 이 모델을 바꾸지 않습니다.

프로젝트별 백그라운드 작업은 하나만 실행합니다. 대화·생성 중에도 다른 페이지나 탭을 볼 수 있고, 브라우저를 닫아도 생성은 이어집니다. 서버 PC가 종료되어 작업이 멈췄으면 작업실에서 취소한 뒤 다시 요청하세요. 취소는 저장을 막으며 이미 저장된 수정본을 지우지는 않습니다. 실행 중인 Ollama 응답은 타임아웃까지 계산을 마칠 수 있습니다.

제한: PPTX 40MB·1~80쪽, 참고 파일 16MB·최대 30개, 한 번에 추가 1~10쪽. 폴더 읽기는 깊이 5, 최대 80개 텍스트 파일·3MB입니다. 원본·수정본·개인 양식은 소유자 인증 후 접근하며 `server/media/`와 DB는 Git에 포함하지 않습니다. 보관함은 삭제가 아닙니다.

코드: `server/presentation_studio/`, `web/features/presentation-studio/`, `web/app/dashBoard/presentations/`. 기존 입찰 서비스에서는 로컬 모델 래퍼·디자인 파일·Office 변환기만 재사용합니다.

## 검증

`manage.py test presentation_studio --noinput`은 원본 보존, 잠금·범위·버전 충돌, 소유자 격리, 개인 양식, 참고자료 접근, 질문·취소 후 파일 보존을 검사합니다. 자동 테스트는 합성 자료를 사용합니다. 사용자 자료의 실제 Gemma/Office 검증은 요청이 있을 때 별도 복사본에서 진행하며 원본 프로젝트를 보존합니다.

2026-09-25 확인: 전체 Django 테스트 224개, 프런트엔드 lint·production build 통과. 실제 `gemma4:26b`로 5쪽 PPTX에 2쪽을 추가하고 기존 5쪽의 XML/관계 바이트 보존, 7쪽 제목만 수정 후 앞 6쪽 보존, 근거 없는 성과 수치에 대한 확인 질문, 업로드 이미지 시각 분석을 확인했습니다. PowerPoint 변환 이미지로 새 페이지와 직접 삽입한 그림을 확인했습니다. 브라우저에서는 양식 확인·잠금, 지침·참고 텍스트, 개인 양식 저장·재사용, AI 작성안 적용, 직접 텍스트·이미지 편집, 페이지 전환 시 단일 미리보기 표시를 검사했습니다. 파일 선택 자동화는 Chrome 확장 권한 제한으로 수행하지 못했으며, PPTX/이미지 업로드는 실제 multipart API로 검증했습니다.

2026-10-06 확인: 전체 Django 테스트 **249개**, 최종 검수 모듈의 추가 재실행 **13개**, lint·production build 통과. 실제 Gemma4 검증용 작성안의 `90% 개선 / 대출 완료`를 검수에서 오류로 판정하고 `도서 등록·검색 구현 / 대출 미구현`으로 한 번 보완했으며 수정하지 않은 4쪽의 바이트 보존과 실제 PowerPoint 렌더링을 확인했습니다. 첫 보완의 성능 미측정 문구 누락은 경고로 표시됐습니다. 이어 만들기에서는 새 페이지의 모든 상자를 작성하도록 보강한 뒤 구현 결과 / 아직 남은 일 / 다음 목표와 미구현·미측정 조건을 확인했고 기존 6쪽이 보존됐습니다. 실제 검수의 표현·배치에 대한 과도한 경고를 줄이도록 보강한 뒤 같은 생성 문구를 재검수했을 때 내용 경고 없이 실제 발췌 인용 3개가 반환됐습니다. 이 검증은 합성 학원 실습 자료이며 사용자의 실제 PPTX 검증은 별도입니다.
