# 제안서 참고 자료 분석

## 분석 범위

- 교육·어학 용역 제안서 7개와 PDF 1개
- 총 448개 슬라이드·페이지
- 원본 파일은 용량과 개인정보 문제로 Git에 저장하지 않음
- 공통 구조와 작성 원칙만 `proposal_generation_rules.json`에 익명화해 저장

## 확인한 공통 흐름

```text
표지
  → 제안 요약
  → 요구사항·평가항목 대응
  → 발주처 현황과 문제
  → 수주 전략과 차별점
  → 세부 수행 방안
  → 일정·조직·인력
  → 품질·위험·보안
  → 성과지표
  → 회사 역량·실적
  → 최종 확인
```

좋은 슬라이드는 `발주처 요구 → 우리 대응 → 실행 방법 → 증빙·KPI`가 한 흐름으로
연결되어 있었습니다. 반대로 교육과정 목록이나 회사 홍보자료를 길게 나열한
슬라이드는 다른 업종에 재사용하기 어렵고 평가항목과의 연결도 약했습니다.

## Bid2 적용 방향

1. 모든 사업에 공통 뼈대를 사용하되 업종별 모듈만 선택합니다.
2. 공고의 평가항목과 배점을 먼저 읽고 슬라이드 분량을 배정합니다.
3. 회사 자료는 사실과 증빙을 추출하는 용도로 사용합니다.
4. 과거 발주처명, 사업명, 날짜와 금액은 새 제안서에 복사하지 않습니다.
5. 텍스트 상자마다 수용 가능한 글자 수를 계산해 AI에 전달합니다.
6. 수용량을 크게 넘는 문장은 자동 삽입하지 않고 검토 대상으로 남깁니다.
7. 슬라이드 묶음별 작성에도 전체 목차를 전달해 같은 설명이 반복되지 않게 합니다.
8. 결과물의 미교체 자리표시자와 빈 슬라이드를 자동으로 다시 확인합니다.

## 업종별 모듈

- 교육 용역: 진단, 교육과정, 강사, 학습 운영, 성과 측정
- 소프트웨어·데이터: 아키텍처, 개발·전환, 시험, 보안, 운영
- 연구·컨설팅: 조사 설계, 자료 수집, 분석, 검증, 정책 제언
- 공사·시설: 현장, 공법, 공정, 안전·품질·환경, 준공
- 물품·제조: 규격, 생산·조달, 검사, 납품·설치, 사후지원
- 일반 용역: 운영 절차, 인력, 서비스 수준, 비상 대응, 개선

## 주의

이 자료는 모델을 별도로 학습시킨 것이 아닙니다. 분석 결과를 프로젝트의
제안서 생성 규칙으로 저장하고, 매번 제안서 생성 프롬프트에서 참고하는 방식입니다.

Microsoft, Canva, Slidesgo 등에는 전문적인 제안 템플릿이 많지만 라이선스와
출처 표시 조건, 자동 입력용 텍스트 상자 구조가 서로 다릅니다. 따라서 파일을
그대로 복사하기보다 일정, 조직, 비교표, KPI 같은 레이아웃 원칙만 참고하고
Bid2가 직접 관리하는 템플릿을 사용하는 방향이 안전합니다.
